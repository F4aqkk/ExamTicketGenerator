Руководство системного программиста
===================================

Документ составлен по ГОСТ 19.503-79 «Руководство системного
программиста. Требования к содержанию и оформлению». В нём же собраны
сведения для разработчика, который будет сопровождать программу.

Общие сведения о программе
--------------------------

Назначение и функции программы описаны в разделе «Описание
применения».

Технические средства: компьютер с Windows 10 или Windows 11.

Программные средства:

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Средство
     - Для чего
   * - Python 3.11+ (разработка велась на 3.14)
     - Язык программы
   * - PyQt6
     - Окна и элементы интерфейса
   * - SQLite
     - База данных в одном файле, без сервера
   * - SQLAlchemy 2
     - Работа с базой из кода (ORM): таблицы описаны классами,
       запросы строятся с параметрами
   * - python-docx, openpyxl, reportlab, pypdf
     - Запись и чтение DOCX, XLSX, PDF
   * - pytest
     - Автоматические тесты
   * - flake8, black
     - Проверка стиля кода (PEP 8) и автоматическое форматирование
   * - PyInstaller
     - Сборка программы в папку с ``ExamTicket.exe``
   * - Sphinx
     - Эта документация
   * - Git, GitHub
     - Хранение кода и история изменений:
       https://github.com/F4aqkk/ExamTicketGenerator

Точные версии библиотек записаны в файле ``requirements.txt``.

Структура программы
-------------------

Программа построена по многослойной архитектуре. Каждый слой
обращается только к слою под ним:

.. code-block:: text

   Окна (app/ui)            — как выглядит и как реагирует на нажатия
        ↓
   Сервисы (app/services)   — правила программы и проверка данных
        ↓
   Репозитории (app/repositories) — чтение и запись таблиц
        ↓
   Модели (app/models)      — описание таблиц базы
        ↓
   База SQLite (exam_tickets.db)

В окнах нет запросов к базе и проверок данных, поэтому правила можно
проверять тестами без интерфейса, а оформление менять, не трогая
правила.

.. list-table:: Состав программы
   :header-rows: 1
   :widths: 35 65

   * - Модуль или папка
     - Что в нём
   * - ``app/main.py``, ``run.py``
     - Точка входа: создаёт приложение, базу и главное окно;
       ``run.py`` — точка входа для сборки exe
   * - ``app/database.py``
     - Подключение к SQLite, включение внешних ключей, создание таблиц
   * - ``app/paths.py``
     - Где искать базу, настройки и значок (при запуске из кода
       и в exe по-разному)
   * - ``app/seed.py``
     - Пересоздание базы с 450 примерами вопросов
   * - ``app/models/``
     - 7 таблиц: ``topics`` (темы), ``questions`` (вопросы), ``tags``
       (теги), ``question_tags`` (связь вопросов и тегов),
       ``generations`` (наборы билетов), ``tickets`` (билеты),
       ``ticket_questions`` (вопросы в билете и их порядок)
   * - ``app/repositories/``
     - ``BaseRepository`` (создать, найти по номеру, все записи,
       количество, изменить, удалить) и репозитории каждой таблицы
   * - ``app/services/question_service.py``
     - Банк вопросов: проверка формы, теги, поиск, темы
   * - ``app/services/ticket_generator.py``
     - Алгоритм составления билетов
   * - ``app/services/generation_service.py``
     - Проверка параметров, составление и сохранение наборов билетов,
       история
   * - ``app/services/export_service.py``,
       ``import_service.py``, ``documents.py``
     - Экспорт билетов и банка, импорт банка, запись и чтение файлов
   * - ``app/services/settings_service.py``
     - Чтение и запись ``settings.json``
   * - ``app/ui/``
     - Главное окно и страницы «Банк вопросов», «Генератор»,
       «История», «Настройки», форма вопроса, оформление (``theme.py``),
       значки (``icons.py``), общие элементы (``widgets.py``)
   * - ``tests/``
     - Автоматические тесты
   * - ``start.bat``, ``build_exe.bat``
     - Запуск одним щелчком и сборка exe

Связи с другими программами: программа не обращается к сети и другим
программам; она только читает и пишет файлы, которые выбрал
пользователь, и файл базы. Подробное описание классов и функций —
в разделе «Описание программного кода».

Настройка программы
-------------------

Подготовка рабочего места разработчика
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Команды выполняются в терминале из папки проекта.

.. code-block:: bat

   git clone https://github.com/F4aqkk/ExamTicketGenerator
   cd ExamTicketGenerator
   py -3 -m venv venv
   venv\Scripts\python.exe -m pip install -r requirements.txt
   venv\Scripts\python.exe -m app.seed
   venv\Scripts\python.exe -m app.main

* ``git clone`` — скачать проект с GitHub;
* ``py -3 -m venv venv`` — создать виртуальное окружение (папку
  ``venv``, где лежат библиотеки только этого проекта);
* ``pip install -r requirements.txt`` — поставить библиотеки нужных
  версий;
* ``-m app.seed`` — создать базу с примерами вопросов (старая база при
  этом удаляется);
* ``-m app.main`` — запустить программу.

Для документации и измерения покрытия тестами дополнительно:

.. code-block:: bat

   venv\Scripts\python.exe -m pip install -r docs\requirements.txt

Файлы данных
~~~~~~~~~~~~

* ``exam_tickets.db`` — база. При запуске из кода берётся из текущей
  папки, поэтому программу нужно запускать из папки проекта. У exe
  база лежит рядом с ``ExamTicket.exe``. Если файла нет, программа
  создаёт пустую базу.
* ``settings.json`` — настройки (организация, дисциплина,
  преподаватель, формат экспорта). Создаётся при первом изменении
  настроек; если файла нет или он испорчен, используются пустые значения
  и формат DOCX.

Оба файла не хранятся в Git (записаны в ``.gitignore``).

Ограничения, заданные в коде
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

* ``BANK_LIMIT = 6000`` (``question_service.py``) — объём банка для
  счётчика «N из 6000»;
* ``MAX_TICKETS = 100`` (``generation_service.py``) — билетов за раз;
* ``MAX_PER_LEVEL = 20`` (``generator_page.py``) — вопросов одной
  сложности в билете.

Сборка exe
~~~~~~~~~~

.. code-block:: bat

   build_exe.bat

Файл запускает PyInstaller, собирает ``dist\ExamTicket\ExamTicket.exe``
вместе с папкой ``_internal`` и копирует рядом текущие
``exam_tickets.db`` и ``settings.json``. Пользователю передаётся вся
папка ``dist\ExamTicket``. Библиотеки для DOCX, XLSX, PDF подключаются
внутри функций, поэтому в сборку они добавлены явно ключами
``--collect-all``.

Документация
~~~~~~~~~~~~

.. code-block:: bat

   build_docs.bat

Собирает эту документацию в ``docs\_build\html``; открыть файл
``index.html``. Раздел «Описание программного кода» Sphinx строит сам
из docstrings, поэтому после изменения кода достаточно пересобрать
документацию.

Проверка программы
------------------

Автоматические тесты
~~~~~~~~~~~~~~~~~~~~

.. code-block:: bat

   venv\Scripts\python.exe -m pytest

Тесты работают с базой SQLite в оперативной памяти: рабочая база
не меняется. Окна в тестах создаются без экрана
(``QT_QPA_PLATFORM=offscreen``, задано в ``tests/conftest.py``).

.. list-table:: Файлы тестов
   :header-rows: 1
   :widths: 35 65

   * - Файл
     - Что проверяет
   * - ``test_topic_repository.py``, ``test_tag_repository.py``,
       ``test_question_repository.py``
     - Создание, чтение, изменение, удаление записей; поиск; запрет
       удаления темы, в которой есть вопросы
   * - ``test_question_service.py``
     - Проверка формы вопроса, разбор тегов, запрет удаления вопроса,
       который стоит в сохранённом билете
   * - ``test_ticket_generator.py``
     - Состав билетов, отсутствие повторов внутри билета, нехватка
       вопросов, правила «не повторять» и «разные темы»
   * - ``test_generation_service.py``
     - Проверка параметров генерации и сохранение набора билетов
   * - ``test_export_import.py``
     - Экспорт билетов с ответами и без, экспорт банка и чтение его
       обратно — во всех четырёх форматах
   * - ``test_settings_service.py``, ``test_paths.py``
     - Настройки и пути к файлам
   * - ``test_ui.py``
     - Окна: открытие, поиск, форма вопроса, генератор, история,
       настройки

Покрытие кода тестами:

.. code-block:: bat

   venv\Scripts\python.exe -m coverage run -m pytest
   venv\Scripts\python.exe -m coverage report

Первая команда запускает тесты и запоминает, какие строки кода
выполнялись, вторая печатает процент покрытия по каждому файлу и номера
непроверенных строк. Что измерять, записано в файле ``.coveragerc``:
только код программы (папка ``app``), включая файлы, которые тесты
не открывают. Результаты — в разделе «Отчёт о тестировании».
Команда ``coverage html`` делает тот же отчёт страницей в папке
``htmlcov``.

Проверка стиля перед коммитом:

.. code-block:: bat

   venv\Scripts\python.exe -m flake8 app tests
   venv\Scripts\python.exe -m black app tests

Контрольный пример
~~~~~~~~~~~~~~~~~~

#. Выполнить ``venv\Scripts\python.exe -m app.seed`` и запустить
   программу. Ожидается: в банке «450 из 6000 записей».
#. В «Генераторе» ввести название, 5 билетов по 1 вопросу каждой
   сложности, отметить все темы, нажать «Сформировать билеты».
   Ожидается: предпросмотр «1 / 5», в каждом билете 3 вопроса разной
   сложности, в «Истории» появилась запись «5 × 3».
#. Экспортировать билеты в PDF с ответами. Ожидается: файл открывается,
   каждый билет на своей странице, русские буквы читаются.
#. В «Банке вопросов» нажать «Экспорт банка», затем «Импорт» того же
   файла. Ожидается: «Добавлено вопросов: 0. Уже были в банке
   и пропущены: 450.»

Скорость работы проверялась на банке из 6000 вопросов: поиск — около
0,1 с, составление 100 билетов по 15 вопросов — около 0,4 с, что
укладывается в требования технического задания (не более 1 с и 6 с).

Защита от SQL-инъекций: все запросы строит SQLAlchemy, значения
передаются в базу параметрами, а не вставляются в текст запроса.

Дополнительные возможности
--------------------------

* Импорт вопросов из PDF, если в нём текст в формате TXT (например,
  файл, сохранённый самой программой).
* Экспорт билетов с ответами — для проверяющего.
* Правило «Разные темы в билете».
* ``start.bat`` сам ставит библиотеки заново, если изменился
  ``requirements.txt``.

Сообщения системному программисту
---------------------------------

Сообщения для пользователя перечислены в «Руководстве оператора».
Ниже — сообщения, которые видит разработчик.

.. list-table::
   :header-rows: 1
   :widths: 35 30 35

   * - Сообщение
     - Причина
     - Действие
   * - ``ModuleNotFoundError: No module named 'PyQt6'`` (или другой
       библиотеки)
     - Запуск не из виртуального окружения или библиотеки
       не установлены
     - Запускать через ``venv\Scripts\python.exe``; выполнить
       ``pip install -r requirements.txt``
   * - ``ModuleNotFoundError: No module named 'app'``
     - Команда запущена не из папки проекта
     - Перейти в папку проекта (``cd``) и повторить
   * - ``sqlite3.OperationalError: no such column`` или ``no such
       table``
     - База создана старой версией программы
     - Пересоздать базу: ``venv\Scripts\python.exe -m app.seed``
       (вопросы сохранить заранее «Экспортом банка»)
   * - ``IntegrityError`` в тексте ошибки
     - Нарушено ограничение базы (например, удаление темы с вопросами)
     - Изменения уже отменены программой; проверить, что сервис
       не допускает такую операцию
   * - ``build_exe.bat``: ``No module named PyInstaller``
     - PyInstaller не установлен
     - ``venv\Scripts\python.exe -m pip install pyinstaller``
   * - ``build_exe.bat``: ``PermissionError`` или «Отказано в доступе»
     - Собранная программа ещё открыта
     - Закрыть ``ExamTicket.exe`` и собрать снова
   * - Exe открывается, но значок старый
     - Windows показывает значок из своей памяти
     - Выполнить ``ie4uinit.exe -show`` (Win+R)

Передача проекта другому разработчику
-------------------------------------

#. Дать доступ к репозиторию на GitHub и ссылку на эту документацию.
#. Новый разработчик готовит рабочее место по разделу «Настройка
   программы» и запускает тесты — все должны пройти.
#. Начать знакомство с кодом с ``app/main.py`` → ``app/ui/main_window.py``
   (какие страницы и сервисы есть) → ``app/services`` (правила)
   → ``app/models`` (таблицы).
#. Правила работы с кодом:

   * каждая задача — в отдельной ветке от ``main``, слияние через
     Pull Request;
   * коммиты маленькие, по одному изменению, сообщение по-русски
     в прошедшем времени («Добавлен …», «Исправлено …»);
   * перед коммитом: flake8 → black → flake8 → pytest;
   * у каждого модуля, класса и функции — docstring на русском языке;
     окна не обращаются к базе напрямую, только через сервисы.

#. Список задач на будущее — в разделе «Бэклог продукта», найденные
   ошибки записываются в раздел Issues на GitHub.
